# ADR-001: onde as leituras ficam guardadas

- **Status:** proposta, aguardando G4 (decisão humana com `lfe approve G4`)
- **Escopo vinculado:** SCOPE-001 (FR-002, FR-003, FR-005)
- **Escolha proposta:** local-only, com `localStorage`

## Contexto

A lista de leituras é pessoal, pequena e não tem login. O escopo pede três coisas que dependem
do armazenamento: a lista sobrevive a recarregar a página (FR-002), a marcação de lida também
(FR-003), e uma falha de gravação aparece para a pessoa em vez de ser escondida (FR-005).
A fatia VS-01 precisa rodar offline, sem conta paga e sem deploy (RFC-0002, seção 1).

## Opções

### Opção 1: local-only (`localStorage`)

Os itens `{id, title, done, createdAt}` ficam na chave `lfe-vs01:readings:v1` do navegador.
O app é HTML, CSS e JavaScript estáticos, sem servidor próprio.

- Privacidade: nada sai do aparelho; não há dado pessoal em servidor.
- Custo e operação: zero; abre direto do disco ou de qualquer servidor estático.
- Falhas: o navegador pode recusar a gravação (cota, janela privada, cookies bloqueados).
  O app trata isso como erro visível (FR-005).
- Limites: a lista fica presa a um navegador e a um aparelho; limpar os dados do site apaga a
  lista; não há sincronização nem backup.

### Opção 2: backend mínimo (Python stdlib + arquivo JSON)

Um `http.server` local recebe `GET` e `PUT` da lista e grava num arquivo JSON no disco.

- Privacidade: continua local se o servidor só escutar em `127.0.0.1`; vira problema assim que
  for exposto na rede.
- Custo e operação: um processo a mais para iniciar, uma porta, gravação concorrente no
  arquivo e um contrato de API para manter.
- Falhas: mais modos de erro (servidor parado, porta ocupada, JSON corrompido), todos
  precisando de estado visível na interface.
- Ganho real: a lista sobrevive à limpeza do navegador e pode ser copiada como arquivo.

## Critérios

| Critério | Local-only | Backend mínimo |
|---|---|---|
| Roda offline, sem conta e sem deploy | sim | sim, com um processo a mais |
| Dados fora do navegador | não | sim |
| Superfície de erro a testar | uma (gravação recusada) | várias (rede, servidor, arquivo) |
| Esforço para a fatia VS-01 | baixo | médio |
| Caminho para sincronizar no futuro | exige migração | parcial (já existe API) |

## Decisão proposta

**Local-only.** Atende FR-002, FR-003 e FR-005 com a menor superfície de erro e mantém a demo
reproduzível sem processo extra. O backend mínimo só compensa quando houver necessidade real
de guardar a lista fora do navegador.

## Consequências

- O app nunca faz requisição de rede. O rodapé diz isso à pessoa.
- A chave tem versão (`:v1`). Uma mudança de formato exige nova chave e migração explícita.
- Dados ilegíveis na chave não são sobrescritos: o app mostra o erro e recusa gravar.
- Duas abas abertas: o app recarrega a lista no evento `storage`, para não gravar por cima de
  dados mais novos.

## Quando revisitar

Se aparecer pedido de usar a lista em mais de um aparelho, de compartilhar com outra pessoa ou
de exportar e importar, esta decisão volta para G4 com a opção 2 ou um serviço gerenciado.
